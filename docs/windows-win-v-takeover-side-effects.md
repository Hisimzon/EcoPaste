# Windows Win+V 接管功能副作用分析

## 实现方式

EcoPaste 没有修改 Windows 剪贴板历史设置，也没有通过普通全局快捷键注册 `Win+V`。

当前实现使用 Windows `WH_KEYBOARD_LL` 低级键盘钩子监听键盘事件。当检测到 Win 键按住并按下 V 键时，会吞掉 V 的按下和抬起事件，再切换 EcoPaste 剪贴板窗口，从而阻止 Windows 原生剪贴板历史面板弹出。

该功能默认关闭。

## 主要副作用

1. 开启后，系统原生 Win+V 面板无法通过键盘打开。这是接管功能的预期行为。
2. 当前代码只判断 Win 键和 V 键，没有排除其他修饰键。因此 `Win+Shift+V`、`Win+Ctrl+V`、`Win+Alt+V` 等组合也会被拦截，并切换 EcoPaste 窗口。
3. 开启期间低级键盘钩子持续驻留。每次键盘事件都会经过钩子回调，但当前回调逻辑较轻，正常情况下性能影响很小。
4. 为避免松开 Win 键后打开开始菜单，代码会通过 `SendInput` 注入一个无实际功能的占位键。安全软件、游戏反作弊、远程桌面或高权限窗口可能拦截该注入，极端情况下可能出现开始菜单闪出。
5. 自动化程序通过 `SendInput` 模拟的 Win+V 会被识别为注入事件并放行，因此不一定能够呼出 EcoPaste。
6. 如果其他软件也通过低级键盘钩子接管 Win+V，最终行为取决于钩子调用顺序，可能出现 EcoPaste 不响应或其他软件快捷键失效。

## 当前代码风险

1. 快捷键录制期间只暂停普通全局快捷键，没有暂停 Win+V 低级键盘钩子。录制包含 Win+V 的组合时，可能直接呼出 EcoPaste。
2. 键盘钩子安装失败时只记录日志，设置仍会显示为开启，用户无法直接知道接管是否真正生效。
3. 快速反复开关功能时，钩子线程启停存在竞态风险，可能造成重复钩子或线程状态跟踪丢失。
4. 电脑睡眠唤醒后没有主动检测钩子是否仍然有效。如果 Windows 移除了钩子，可能出现设置显示开启但 Win+V 不再响应，直到重新切换设置或重启应用。

## 不会造成的影响

1. 不会清除或关闭 Windows 剪贴板历史数据。
2. 不会修改注册表或永久修改系统 Win+V 设置。
3. EcoPaste 正常退出或异常退出后，Windows 会自动移除进程键盘钩子，原生 Win+V 会自动恢复。
4. 普通 V 键和 `Ctrl+V` 不受影响。

## 建议

该功能继续保持默认关闭是合理的。正式推广前建议优先处理以下问题：

1. 只接管没有额外修饰键的纯 `Win+V`。
2. 快捷键录制期间同步暂停 Win+V 钩子。
3. 将钩子安装结果反馈到设置界面。
4. 增加睡眠唤醒后的钩子健康检查和重新安装逻辑。
5. 串行化钩子启停，避免快速切换产生线程竞态。
